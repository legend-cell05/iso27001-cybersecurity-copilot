# The demo organisation

> **Meridian Logistics SAS does not exist.** Every asset, risk, control
> decision, acceptance and evidence record below is generated by
> `sentinel demo`, deterministically from a seed. No real organisation is
> described, and no artefact referenced by the evidence index is a real file.

---

## 1. Who they are

A French freight forwarder with two sites — Lyon and Lille — running a
self-built booking platform, an invoicing system, a carrier telematics
integration and a customs broker portal. ISMS scope:

> The information systems supporting freight booking and customer data
> processing, at the Lyon and Lille sites.

The register holds **22 assets** and **28 risks**: credential theft, ransomware
through an unpatched depot host, a leaving driver with a handheld, build
secrets in a CI pipeline, a carrier integration nobody reviews, invoice fraud
by bank-detail change. They were chosen to be the risks a logistics company
actually carries rather than a generic list, because a risk nobody recognises
cannot be argued with either.

## 4. Determinism

`SENTINEL_RANDOM_SEED` (20260927 by default) fixes the generator, and the demo
is built around a **fixed reference date**, 2026-09-27, rather than "today".

That second part matters more than it looks. The ages of evidence, acceptances
and audits are the whole point of several rules, and a demo whose findings
change with the calendar cannot be documented — the numbers in this file would
be wrong by the time anybody read them. `sentinel assess` uses the real date;
the tests and the figures here pass the fixed one.

---

## 5. The evidence hashes are honest about being fake

Every evidence record carries a SHA-256. The demo's artefacts do not exist, so
inventing a plausible-looking digest that is not the hash of anything would be
exactly the dishonesty this project argues against elsewhere.

Instead each one is the hash of its own label:

```python
hashlib.sha256(f"meridian-demo::{label}".encode()).hexdigest()
```

Reproducible, verifiable, and obviously synthetic to anyone who checks.

## 6. Running it

```bash
sentinel demo --profile gaps     # the ISMS mid-programme
sentinel assess                  # 44 findings, 11 blocking
sentinel readiness               # exit code 3
sentinel export                  # SoA, treatment plan, findings, dossier

sentinel demo --profile ready    # the same organisation, remediated
sentinel readiness               # exit code 0
```

`sentinel cycle --profile gaps` does the whole sequence in one command, which
is what the CI job runs.
